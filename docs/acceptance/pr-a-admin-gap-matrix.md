> 生成方式：分别只读巡检两份源码（shadcn-admin 与 `zeus` 仓库的 `examples/admin`），再交叉比对；Zeus 侧的证据是仓库内相对路径，参考侧的证据给出 shadcn-admin 仓库内路径（浅克隆 `satnaing/shadcn-admin` 后逐条核对）。
> 参考基线：`satnaing/shadcn-admin` 浅克隆当日 `main`（Vite + React + TanStack Router/Table + shadcn/ui）。
> 状态口径：`已有且完整` / `已有但交互不完整` / `尚未实现` / `不适合 Zeus Admin 定位`。

## 3. 技术约束（实施时必须保持）

- 不重写 React：保留 Zeus 原生 TSX + @zeus-js/\* 架构（createSignal/createMemo/createEffect/Show/For），参考实现只作为行为与视觉基线。
- 保留 Router / Query / Session / CSRF / RBAC 现有链路：@zeus-js/router loader 与 redirect、useQuery/useMutation 缓存、SessionContext、X-CSRF-Token、服务端每次请求重校验角色。
- 保持 shadcn 视觉基线：以 tokens.css 的 oklch token 与 base.css atoms 为唯一视觉源，不引入第二套样式体系或按页面写死颜色。
- 优先复用 zeus-ui 既有原语（@zeus-web/\* 0.1.0-beta.35：data-grid/input/dialog/toast/tabs/select/checkbox/radio-group/switch/popover/tooltip/form-field/skeleton 等），不在示例里堆积一次性手写组件。
- 业务页不允许假后端：所有计数、列表、筛选、写操作必须走真实 API；只有 VITE_ZEUS_ADMIN_DEMO 构建可读构建期快照且写操作必须明确拒绝。
- 保持 i18n 覆盖：en 与 zh-CN 键集必须一致（当前各 209 键），新增文案双语；禁止 audit 时间 toLocaleString('zh-CN')、router 403/404 中文文案这类硬编码。
- 键盘可达：焦点陷阱/inert、Escape 关闭、Arrow/Home/End roving tabindex、aria-modal/aria-live/role=status 必须随新组件补齐。
- 移动端：<768px 抽屉导航与批量操作浮动工具栏、<1024px 设置侧导航切换、<1280px top-nav 回退都要有可用入口，不能只 display:none。
